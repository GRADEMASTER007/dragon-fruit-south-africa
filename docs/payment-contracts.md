# Official payment contracts researched 15 October 2026

## PayFast

Sources fetched: https://developers.payfast.co.za/docs , https://developers.payfast.co.za/ , https://developers.payfast.co.za/api . Custom hosted form POST actions are `https://sandbox.payfast.co.za/eng/process` and `https://www.payfast.co.za/eng/process`; ITN confirmation endpoints are matching `/eng/query/validate`. Required application fields include merchant_id, merchant_key, return_url, cancel_url, notify_url, name_first/name_last/email_address, m_payment_id, amount, item_name. Fields are signed in documentation/received order, excluding signature/empty values, PHP-style URL encoding (spaces +, encoded punctuation and uppercase hex), optional passphrase appended last, MD5 digest. This differs from alphabetically sorted REST API signatures. The passphrase stays server-only; merchant_id/key are PayFast-required hosted-form identifiers, not a substitute for signing credentials.

ITN must verify signature, merchant/reference/amount_gross, PayFast origin/IP policy and official server confirmation exactly VALID. Current statuses COMPLETE and CANCELLED. Deduplicate pf_payment_id + payment_status; a cancelled callback cannot reverse a captured payment. Browser return is never proof. Official source host list: www.payfast.co.za, w1w.payfast.co.za, w2w.payfast.co.za, sandbox.payfast.co.za. Manus proxy does not currently expose a documented trusted original-client-IP contract; do not trust spoofable X-Forwarded-For/Referer. Therefore live PayFast stays blocked until this requirement is resolved; sandbox code tests are not proof of production acceptance. Do not store raw protected callback payloads; retain minimal event/reference/status results.

## Yoco

Sources fetched: https://developer.yoco.com/api-reference/checkout-api/checkout/create-checkout.md , https://developer.yoco.com/docs/checkout-api/idempotency.md , https://developer.yoco.com/openapi/checkout-api-reference.json , https://developer.yoco.com/guides/online-payments/accepting-a-payment.md , https://developer.yoco.com/docs/checkout-api/authentication.md , https://developer.yoco.com/docs/checkout-api/testing.md , https://developer.yoco.com/api-reference/checkout-api/webhooks/register-webhook.md , https://developer.yoco.com/guides/online-payments/webhooks/listen-for-events.md , https://developer.yoco.com/guides/online-payments/webhooks/verifying-the-events.md , https://developer.yoco.com/api-reference/checkout-api/webhook-events/payment-notification.md .

POST `https://payments.yoco.com/api/checkouts`: Bearer sk_test_/sk_live_ secret; Idempotency-Key stable UUID; integer ZAR cents (minimum 200), success/cancel/failure URLs, server-owned metadata, externalId/clientReferenceId. Response id, redirectUrl, amount, currency, merchantId and processingMode must match. Key reuse same payload replays result; different payload 422, concurrent 409; key retention 24h. No current documented GET /api/checkouts/{id}: do not invent one. Signed webhook is authoritative. Separate Yoco read-only Payments API requires its own scoped JWT business/orders:read, not merely Checkout secret key.

Webhook registration POST `/api/webhooks` returns secret once; no registration was performed. Headers webhook-id, webhook-timestamp, webhook-signature; signing content id.timestamp.rawBody, HMAC-SHA256 using Base64-decoded whsec_ suffix; test v1 signatures constant time; max 180s timestamp tolerance. Event id dedupe; types payment.succeeded/payment.failed; payload has id/payment reference, integer amount, ZAR, test/live mode, matching status and metadata.checkoutId. Validate stored checkout ID, amount, currency, mode. No documented merchant/account field in webhook: isolation is configured webhook signing secret and merchantId retained on creation. Live domain approval required; real sandbox verification remains credential-blocked.

## PayPal

Sources fetched: https://developer.paypal.com/api/orders/v2/schema.json , https://developer.paypal.com/api/orders/v2/orders-capture , https://developer.paypal.com/api/payments/v2/schema.json , https://developer.paypal.com/api/webhooks/v1/schema.json , https://developer.paypal.com/api/rest/reference/idempotency , https://developer.paypal.com/reports/reference/supported-currencies , https://developer.paypal.com/api/codes/currency .

Sandbox base https://api-m.sandbox.paypal.com ; live https://api-m.paypal.com . OAuth POST /v1/oauth2/token Basic(client ID:secret), grant_type=client_credentials. Server Orders POST /v2/checkout/orders with intent CAPTURE, immutable amount/currency, reference_id/invoice_id/custom_id, expected payee.merchant_id. Use payment_source.paypal.experience_context return/cancel URL/user_action PAY_NOW. Redirect only returned approve/payer-action URL. PayPal-Request-Id stable per logical operation, different UUID for create versus capture. Server POST order/{id}/capture then authoritative GET; only matching completed capture and order, amount/currency/payee/internal reference can fulfil. Browser approval is not capture.

Webhook server verification POST /v1/notifications/verify-webhook-signature: auth_algo, cert_url, transmission_id, transmission_sig, transmission_time from PAYPAL-* headers; configured webhook_id; complete webhook_event. Require verification_status SUCCESS. Events PAYMENT.CAPTURE.COMPLETED/PENDING/DENIED/REFUNDED; refunded resource is refund not capture. Read-only reconciliation GET /v2/payments/captures/{id} and /v2/payments/refunds/{id}; no automatic refund submission. Never store raw protected financial payloads unnecessarily.

Official currency list contains USD but not ZAR. Owner's PayPal supported-currency quotation/conversion choice is still unanswered: no exchange rate may be invented and no ZAR Checkout request may be sent. Creation adapter is gated on USD; PayPal checkout, capture and webhook workflow remain unavailable until the approved business flow is implemented and verified.
